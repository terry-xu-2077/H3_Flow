# V0.8 后端适配：AI 提示词增强与历史版本

> 日期：2026-09-13  
> 基于：`V0.5_BACKEND_FRONTEND_ADAPTER.md` + `V0.6_BACKEND_DELTA.md`

## 1. 目标

AI 增强不再是 Task 上的单一字符串，而是：

```text
用户提示词
  ↓ AI Enhancement Service
AI 增强版本 1
AI 增强版本 2
AI 增强版本 3 ...
```

前端当前选中的历史版本即 `aiPrompt` / `finalPrompt` 的来源。

---

## 2. 推荐接口

```http
POST /api/v1/projects/{projectId}/tasks/{taskId}/prompt-enhancements
```

请求：

```ts
type PromptEnhancementRequest = {
  taskId: string;
  userPrompt: string;
  previousTaskSummary?: string;
  projectBackground?: string;
  assets: Array<{
    id: string;
    name: string;
    reference: string;
    kind: "subject" | "picture" | "video" | "audio";
  }>;
  generation: {
    resolution: "480p" | "720p" | "1080p";
    quality: "快速" | "标准" | "高质量";
    mode: "全能参考" | "首尾帧";
    durationSeconds: number;
    contextMode: "片段承接" | "尾帧承接" | "不承接";
    contextStartSeconds?: number;
    contextEndSeconds?: number;
  };
};
```

响应：

```ts
type PromptEnhancementResponse = {
  id: string;
  createdAt: string;
  prompt: string;
};
```

## 3. 上一任务上下文规则

### 3.1 只提供摘要文本

Adapter 在构建 TaskEditorView 或增强请求时，应解析 Story Order 得到上一任务，并提供：

```ts
previousTaskSummary: string | null;
```

来源优先级：

```text
上一任务 summary
→ 简短 userIntent
→ 任务标题
```

**默认禁止把上一任务完整 Prompt 作为增强上下文。**

不要默认发送：

- `previousTask.userPrompt` 全文；
- `previousTask.aiPrompt` 全文；
- `previousTask.finalPrompt` 全文；
- 完整 Result 文本；
- ContextLink / Job / Provider 内部对象。

原因：上一任务 Prompt 通常包含大量局部镜头细节，直接传递会导致当前任务被旧镜头参数、动作和构图过度污染。摘要更适合承担叙事连续性上下文。

### 3.2 摘要长度

建议 Adapter / Summary Service 将上一任务摘要控制在较短文本范围内，例如 1–4 句。

未来如需要更强的视觉连续性，应通过独立的 visual/native context 通道解决，不要继续无限扩张 `previousTaskSummary`。

## 4. 项目背景

只有：

```text
project.useDescriptionForAiPrompt == true
```

且 description 非空时才发送：

```ts
projectBackground: string;
```

后端不能自行绕过项目开关。

---

## 5. AI 历史版本模型

推荐后端正式模型：

```ts
type AiPromptRevision = {
  id: string;
  taskId: string;
  createdAt: string;
  prompt: string;
  sourceUserPrompt: string;
  previousTaskSummary?: string;
  projectBackgroundUsed: boolean;
  assetIds: string[];
  modelId?: string;
  providerId?: string;
};
```

TaskEditorView 增量：

```ts
type TaskEditorView = {
  // ...既有字段
  promptSource: "user" | "ai";
  userPrompt: string;
  aiEnhancedPrompt: string;
  selectedAiPromptHistoryId?: string;
  aiPromptHistory: AiPromptRevision[];
  previousTaskSummary?: string;
};
```

### 5.1 不覆盖历史

每次点击“增强”：

1. 新建一条 `AiPromptRevision`；
2. 不覆盖旧版本；
3. 返回新版本；
4. 前端自动选中新版本。

---

## 6. 保存 Task

保存任务时：

```text
promptSource == user
  → finalPrompt = userPrompt

promptSource == ai
  → finalPrompt = 当前 selectedAiPromptHistoryId 对应 prompt
```

为了兼容当前领域模型，可以继续冗余保存：

```ts
aiPrompt: string;
```

其值等于当前选中 AI 版本的文本，但历史的真实来源应以 `AiPromptRevision` 为准。

---

## 7. 推荐读取接口

TaskEditorView 可以直接附带最近若干 AI 版本；如果版本数量未来很多，再拆成：

```http
GET /api/v1/projects/{projectId}/tasks/{taskId}/prompt-enhancements
```

当前阶段不需要为了少量历史版本提前引入分页 UI。

---

## 8. 失败与重试

AI Enhancement 是可重试操作：

- 请求失败不修改当前历史；
- 再次点击“增强”发起新请求；
- 不将失败尝试伪装成历史版本；
- 后端如支持 requestId，可用于防重复提交和追踪日志。

---

## 9. 前端当前过渡实现

当前前端开发阶段：

- 历史暂存于 `generationParams.aiPromptHistory`；
- 当前选择暂存于 `generationParams.selectedAiPromptHistoryId`；
- 旧 `aiPrompt` 自动迁移为一条 legacy 版本；
- DEV 环境在后端接口尚未接入时可使用确定性预览结果，便于验证 UI 流程；
- 生产环境必须调用真实 Prompt Enhancement Adapter，不允许静默伪造 AI 结果。

后端正式落地后，再由 Repository / Adapter 将这些临时字段迁移到正式 revision 模型。

---

## 10. 验收

- [ ] 后端能创建多个 AI 增强版本；
- [ ] 每次增强不覆盖旧版本；
- [ ] previousTaskSummary 来自 Story Order 的上一任务摘要；
- [ ] 默认不发送上一任务完整 Prompt；
- [ ] 项目背景受项目开关控制；
- [ ] 当前 AI 版本可被保存为 finalPrompt；
- [ ] 旧单一 aiPrompt 能迁移；
- [ ] 失败增强不会产生伪历史记录。
