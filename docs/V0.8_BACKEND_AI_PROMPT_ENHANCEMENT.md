# V0.8 后端适配：AI 提示词增强与历史版本

> 日期：2026-09-13  
> 状态：**版本增量文档**  
> AI 提示词增强的长期架构以 [`AI_PROMPT_ENHANCEMENT_ARCHITECTURE.md`](./AI_PROMPT_ENHANCEMENT_ARCHITECTURE.md) 为最高优先级。本文件只保留 V0.8 UI / 数据迁移相关说明。

## 1. V0.8 目标

V0.8 将 AI 增强从 Task 上的单一字符串升级为可重复生成、可切换的历史版本：

```text
用户提示词
  ↓ AI Enhancement Service
AI 增强版本 1
AI 增强版本 2
AI 增强版本 3 ...
```

前端当前选中的 AI 历史版本可作为 `aiPrompt / finalPrompt` 来源。

正式 AI Enhancement Service 的多模态输入、Skill、Provider Adapter、媒体上传 / 内联 / 抽帧等规则见专项架构文档。

---

## 2. 当前推荐接口

```http
POST /api/v1/projects/{projectId}/tasks/{taskId}/prompt-enhancements
```

新建 Task 首次保存前使用无残留预览接口：

```http
POST /api/v1/projects/{projectId}/prompt-enhancement-previews
```

预览接口接收相同的 Prompt、媒体、Context 与生成参数，并可额外携带稳定的 `previousTaskId`。它只返回本次增强结果，不创建 Task 或 `AiPromptRevision`；保存新 Task 后才开始正式历史。

V0.8 前端过渡请求可以继续兼容已有字段，但正式后端应逐步迁移为：

```ts
type PromptEnhancementRequest = {
  taskId: string;
  target: "minimax-h3" | "seedance-2.0" | string;
  userPrompt: string;

  media: Array<{
    assetId: string;
    reference: string;
    role?: string;
  }>;

  context: {
    includeProjectBackground: boolean;
    includePreviousTaskSummary: boolean;
  };

  generation: {
    durationSeconds: number;
    mode: string;
    contextMode?: string;
  };
};
```

响应：

```ts
type PromptEnhancementResponse = {
  id: string;
  createdAt: string;
  prompt: string;
};
```

## 3. 上一任务摘要是可选上下文

旧版设计把 `previousTaskSummary` 近似当作默认增强上下文；该规则已废止。

正确规则：

```ts
includePreviousTaskSummary: boolean;
previousTaskSummary?: string;
```

只有 `includePreviousTaskSummary == true` 时，才允许把上一任务摘要提供给 Prompt Enhancer。

摘要来源仍建议：

```text
上一任务 summary
→ 简短 userIntent
→ title（兜底）
```

即使启用摘要，也默认禁止发送上一任务完整：

- `userPrompt`；
- `aiPrompt`；
- `finalPrompt`；
- Result 全文；
- Job / ContextLink / Provider 内部对象。

Prompt Enhancement Context 与 Video Generation Context 必须保持独立。

---

## 4. 项目背景同样是可选上下文

项目背景是否参与 AI 增强，由项目配置控制：

```text
useDescriptionForAiPrompt
```

正式请求应映射为：

```ts
includeProjectBackground: boolean;
```

后端不能自行绕过用户设置。

---

## 5. 当前任务实际媒体是核心输入

资产名、引用标签和 assetId 只是元数据。

正式后端必须：

```text
assetId
→ 解析项目真实资产
→ Prompt Enhancement Adapter
→ 真正的 image / video multimodal parts
```

不得把：

```text
“林澜·雨夜造型 <Picture 1>”
```

这种字符串当作视觉素材的替代品。

Provider 的文件上传、base64、video_url、视频抽帧等能力全部由 Prompt AI Provider Adapter 负责。

## 6. AI 历史版本模型

推荐正式模型：

```ts
type AiPromptRevision = {
  id: string;
  taskId: string;
  createdAt: string;
  prompt: string;
  sourceUserPrompt: string;

  targetSkill: string;
  assetIds: string[];

  includeProjectBackground: boolean;
  includePreviousTaskSummary: boolean;
  previousTaskSummarySnapshot?: string;

  modelId?: string;
  providerId?: string;
  skillVersion?: string;
};
```

对已经保存的 Task，每次点击“增强”：

1. 新建 revision；
2. 不覆盖旧版本；
3. 返回新版本；
4. 前端自动选中新版本。

对尚未保存的新 Task，每次点击“增强”只产生当前编辑会话内的预览版本。取消编辑不留下数据库记录；保存时仅保存当前 AI Prompt，不伪造历史 revision。

---

## 7. 保存 Task

```text
promptSource == user
  → finalPrompt = userPrompt

promptSource == ai
  → finalPrompt = 当前 selectedAiPromptHistoryId 对应 prompt
```

为了兼容当前领域模型，可以暂时冗余保存：

```ts
aiPrompt: string;
```

但正式历史来源以 `AiPromptRevision` 为准。

---

## 8. 当前前端过渡实现

当前 V0.8 前端仍存在过渡代码：

- 历史暂存于 `generationParams.aiPromptHistory`；
- 当前选择暂存于 `generationParams.selectedAiPromptHistoryId`；
- 旧 `aiPrompt` 自动迁移为一条 legacy 版本；
- DEV 环境可能使用确定性预览结果；
- 当前 service 仍可能直接携带摘要文本和资产元信息。

这些只是 UI 联调实现，不代表正式架构。

正式后端完成后应迁移到：

```text
前端：assetId + role + context options
后端：解析实际媒体
Skill：生成目标视频模型专属 Prompt
Provider Adapter：真正发送多模态输入
Repository：保存 AiPromptRevision
```

## 9. 验收

- [x] 已保存 Task 每次增强产生独立 revision，不覆盖旧版本；
- [x] 实际引用图片 / 视频会作为真实多模态输入发送；
- [x] 资产元信息不能代替媒体本体；
- [x] `includePreviousTaskSummary=false` 时不发送上一任务摘要；
- [x] 启用摘要时仍不默认发送上一任务完整 Prompt；
- [x] 项目背景受用户开关控制；
- [x] H3 / Seedance 使用不同 Prompt Skill；
- [x] Prompt AI Provider Adapter 负责媒体传输并按 Capability 明确拒绝不支持的降级路径；
- [x] 当前 AI 版本可被保存为 finalPrompt；
- [x] 新建 Task 可先增强再保存，取消时不产生 Task / Revision 残留；
- [x] 失败增强不会产生伪历史记录。
