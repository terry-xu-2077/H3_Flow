# ShotMill V0.5「Terry导演工作台」UI 基线

> 状态：V0.5 起强制执行  
> 更新时间：2026-09-13  
> 适用范围：桌面端主产品界面、`/dev/ui`、后续真实后端接入  
> 设计来源：2026-09-13 用户确认的首页、列表模式项目页、卡片模式项目页草图

## 0. 产品心智

V0.5 开始，ShotMill 的默认产品不再表现为多个工具工作区，而是一个极简的导演任务工作台。

用户只需要理解三层：

```text
项目首页
  ↓ 选择 / 新建项目
项目工作台
  ↓ 双击 / 右键 / 新建任务
任务编辑弹窗
```

内部仍可保留 `GenerationTask / Job / Result / Asset / Context / Provider / Profile` 等复杂领域模型，但默认界面不得按这些内部模型拆分导航。

核心原则：

> **首页只选项目，项目页只管理任务，任务内容只在弹窗里编辑。**

> **列表和卡片只是同一份任务数据的两种视图，不是两个功能模块。**

> **运行状态是底部状态信息，不再为了后台模型额外建立默认一级页面。**

---

# 1. 一级页面结构

桌面端默认只保留两个真正的页面：

1. **项目首页**：选择已有项目或新建项目。
2. **项目工作台**：查看、选择、创建、编辑当前项目的任务。

任务编辑、项目设置、资产选择等全部使用 Overlay / Dialog，不占用一级页面。

禁止重新增加以下默认一级页面或侧边导航：

- 故事板；
- 生成；
- 素材；
- 结果；
- Provider；
- Profile；
- Prompt；
- Job；
- Context。

这些能力仍然存在，但必须围绕“项目”和“任务”自然进入。

---

# 2. 项目首页

## 2.1 页面职责

项目首页只做两件事：

- 打开已有项目；
- 新建项目。

不得在首页出现任务编辑、生成参数、资产详情、队列详情等项目内部信息。

## 2.2 布局

草图基线：

```text
────────────────── [ Terry导演工作台 ] ──────────────────

      [项目 01]   [项目 02]   [项目 03]
      [新建项目]

──────────────────────────────────────────────────────────
```

页面没有左侧导航栏。

标题位于顶部中央，并通过简洁边框 / 标签结构与两侧水平分割线形成视觉中心。

## 2.3 项目卡

项目卡采用“文件夹”视觉隐喻，允许保留轻量的文件夹折角 / 页签轮廓。

每张已有项目卡只显示：

1. 项目序号；
2. 项目状态；
3. 封面；
4. 项目名称；
5. `任务数量 / 资产数量`。

状态仅使用文字 + 单个状态点：

- 灰：未开始；
- 黄：进行中；
- 绿：已完成。

不得增加多个 Badge、模型名、队列详情、Provider、磁盘路径等技术信息。

## 2.4 新建项目卡

新建项目使用与项目卡相近的文件夹轮廓，但内容只显示：

```text
＋ 新建项目
```

点击后打开“新建项目”弹窗。

## 2.5 首页交互

- 单击已有项目：进入项目工作台；
- 单击新建项目：打开新建项目弹窗；
- 首页不提供任务级右键菜单；
- 返回首页时保留项目列表滚动位置（真实实现阶段）。

---

# 3. 项目工作台

## 3.1 总体布局

项目工作台由四个稳定区域组成：

```text
┌──────────────────────────────────────────────────────────────┐
│ Terry导演工作台 │       📁 当前项目名 ✎       │ 表格 / 卡片 │
├───────────────────────────────────────────┬──────────────────┤
│                                           │                  │
│              任务主区域                   │   右侧只读栏     │
│          （列表 或 卡片）                 │                  │
│                                           │                  │
├───────────────────────────────────────────┴──────────────────┤
│ ⚙ 设置                       ● 当前运行：项目名 · 任务名    │
└──────────────────────────────────────────────────────────────┘
```

结构不可随视图模式变化。

## 3.2 顶部栏

### 左侧

固定显示：

`Terry导演工作台`

点击后返回项目首页。

### 中间

显示：

- 文件夹图标；
- 当前项目名；
- 重命名图标。

项目名是当前页面最重要的上下文，不显示多层面包屑。

### 右侧

只有视图切换：

- 表格；
- 卡片。

切换只改变任务主区域的排版，不更换数据、选中状态或编辑逻辑。

---

# 4. 列表模式

## 4.1 新建任务入口

列表模式必须包含明确的 **`＋ 新建任务`** 按钮。

建议位置：任务列表上方左侧或第一行之前，必须无需右键或隐藏菜单即可发现。

点击后：

1. 创建一个本地空白草稿任务；
2. 立即打开与已有任务完全相同的任务编辑弹窗；
3. 用户保存后任务正式保留；
4. 用户取消时，未保存的新草稿不应污染项目任务列表（真实数据接入阶段由 Draft 事务语义保证）。

## 4.2 任务行

每一行最多显示：

- 小缩略图；
- `#序号 + 任务标题`；
- 一行提示词摘要；
- 使用资产数量；
- 生成版本数量 / 无生成结果；
- 状态。

状态：

- 未开始；
- 进行中；
- 已完成；
- 失败（必要时）。

任务行不出现编辑表单。

## 4.3 列表交互

- 单击：选中任务并更新右侧只读信息栏；
- 双击：打开任务编辑弹窗；
- 右键：出现任务菜单，至少包含“编辑任务”；
- 列表与卡片模式共享 `selectedTaskId`。

---

# 5. 卡片模式

## 5.1 新建任务卡

第一张卡固定为“新建任务卡”：

```text
┌─────────────┐
│      ＋      │
│             │
│   新建任务卡 │
└─────────────┘
```

点击行为与列表模式的“新建任务”按钮完全一致。

## 5.2 任务卡

每张卡最多显示：

1. 预览 / 封面；
2. 状态；
3. `#序号 + 标题`；
4. 提示词摘要；
5. `资产数量 / 生成版本数量`。

任务卡不再额外显示模型、Profile、Context、Job、内部 ID 等信息。

## 5.3 卡片交互

与列表完全一致：

- 单击：选择；
- 双击：编辑；
- 右键：任务菜单；
- 选中状态同步右侧只读栏。

---

# 6. 右侧只读信息栏

右栏在列表 / 卡片模式下完全一致。

只显示：

1. 当前任务预览；
2. 任务名称；
3. 提示词摘要；
4. 生成参数摘要。

必要时可增加“生成结果版本数”等纯信息，但不得演变成参数面板。

右侧栏强制禁止：

- input；
- textarea；
- Select；
- 保存；
- 添加素材；
- 修改参数；
- Prompt 编辑；
- Profile / Provider / Capability；
- Job / Context 调试；
- 任何修改任务内容的操作。

右栏唯一职责：**帮助用户确认当前选中的任务是什么。**

---

# 7. 任务编辑

任务编辑继续沿用 V0.4 已确认的悬浮编辑窗。

入口：

- 双击任务；
- 右键 → 编辑任务；
- 列表模式“新建任务”；
- 卡片模式“新建任务卡”。

编辑窗固定为：

```text
┌──────────────┬────────────────────────────────────┐
│   任务配置   │            提示词编辑              │
│              │                        用户 | AI增强│
│ 生成参数     │                                    │
│ 生成模式     │            大面积编辑区            │
│ 上下文承接   │                                    │
├──────────────┴────────────────────────────────────┤
│                               取消      保存       │
└───────────────────────────────────────────────────┘
```

不得重新恢复旧 Task Composer 参数墙。

---

# 8. 底部状态栏

## 8.1 左侧

固定显示：

`⚙ 设置`

点击打开项目 / 应用设置弹窗，不跳转一级页面。

## 8.2 右侧

显示当前正在运行的生成任务：

```text
● 当前运行：异星边境 初到基地 · 任务名：XXXXXX
```

无正在运行任务时显示：

```text
当前没有正在运行的任务
```

状态栏只做摘要，不展开队列。

---

# 9. 项目状态定义

首页项目状态由项目内任务自动聚合，而不是单独让用户维护。

推荐规则：

```text
如果存在 running / queued 任务 → 进行中
否则如果项目至少有任务且全部主要任务已完成 → 已完成
否则 → 未开始
```

后端最终可根据真实业务规则细化，但前端只消费聚合后的状态。

---

# 10. 生成版本概念

草图中的“3 个生成版本 / 1 个生成版本 / 无生成结果”映射为 Task 下历史 `Result` 数量。

前端默认只显示数量，不在主列表展开 Result ID 或 Job ID。

后续如需选择版本，应通过任务预览或专用结果选择 Overlay 进入，不改变主工作台结构。

---

# 11. 素材入口

V0.5 不再把“素材”作为一级页面。

素材的主要进入方式：

- 任务编辑窗中的 `@` 引用；
- 任务编辑窗内的素材选择 Overlay（需要时）；
- 项目设置中的项目素材管理入口（后续阶段）。

内部仍保留 Asset Library 数据模型和已有组件能力，但默认产品导航不再暴露一个独立“素材工作区”。

---

# 12. 生成监控入口

V0.5 不再把“生成”作为默认一级页面。

主要状态通过：

- 任务行 / 卡状态；
- 底部当前运行状态；
- 右侧任务只读栏；

完成日常监控。

完整队列 / 历史任务监控若未来确有必要，应以设置 / 状态弹窗或辅助窗口提供，不得重新抢占一级导航。

---

# 13. 空状态

## 13.1 无项目

首页只显示：

- Terry导演工作台；
- 新建项目卡。

## 13.2 空项目

项目页：

- 列表模式显示“新建任务”按钮 + 简洁空提示；
- 卡片模式只显示“新建任务卡”；
- 右栏显示“选择一个任务查看信息”。

---

# 14. 响应式原则

本阶段优先桌面端。

当宽度不足时：

1. 优先缩小右侧只读栏；
2. 再允许右栏临时折叠；
3. 不把任务信息重新塞到主列表中；
4. 不改变双击 / 右键进入编辑的规则。

移动端进度页仍是独立后续需求，不直接复刻桌面工作台。

---

# 15. 视觉原则

- 结构比装饰重要；
- 大留白允许存在；
- 线框 / 分割线清楚但克制；
- 高饱和色只用于状态点、选中态、警告；
- 不使用大面积渐变；
- 不堆 Badge；
- 不堆参数；
- 任务封面 / 视频预览比 UI 装饰更重要；
- 文件夹造型是项目层级的视觉语言，不要求任务卡也使用文件夹形状。

---

# 16. V0.5 前端状态模型

前端页面级状态建议固定为：

```ts
type AppPage = "home" | "project";
type TaskViewMode = "list" | "card";

currentProjectId: string | null
selectedTaskId: string | null
taskViewMode: TaskViewMode
taskEditorTaskId: string | null
creatingTask: boolean
```

不要再使用 `activeNav = storyboard | production | assets` 作为主产品路由模型。

# 18. 冲突优先级

涉及默认产品 UI 时：

1. 最新明确需求；
2. 本文 `UI_V0.5_PROJECT_WORKSPACE.md`；
3. `UI_DIRECTOR_MODE_GUIDE.md` 中未与本文冲突的查看/编辑与防参数墙规则；
4. `UI_UX_SPEC.md` 通用 Overlay / 视觉 / 测试协议；
5. 旧 V0.2 / V0.3 界面文档仅作为历史能力参考。

V0.5 的结构决策是：

> **项目首页 → 项目工作台 → 任务编辑弹窗。**

不得再使用旧一级导航覆盖这一结构。
