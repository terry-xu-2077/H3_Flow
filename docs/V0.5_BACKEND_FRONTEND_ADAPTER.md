# ShotMill V0.5 后端适配新前端方案

> 状态：V0.5 前端重构后的后端接入契约  
> 更新时间：2026-09-13  
> 对应 UI：`UI_V0.5_PROJECT_WORKSPACE.md`

## 0. 当前情况

当前 `backend/shotmill/app.py` 只有：

- `/`；
- `/health`；
- FastAPI / CORS 基础壳。

项目、任务、资产、Job、Result、Context 等领域能力目前主要仍停留在前端 Mock / 文档模型阶段，因此 V0.5 不应该让前端直接围绕数据库表或内部领域对象拼 API。

后端接入的目标不是“把现有 `GenerationTask` JSON 原样吐给前端”，而是增加一层 **Frontend Adapter / Read Model**：

```text
Core Domain
Project / GenerationTask / Job / Result / Asset / Context
                    ↓
            Frontend Adapter
      聚合 / 翻译 / 隐藏内部复杂度
                    ↓
V0.5 UI
项目首页 / 项目工作台 / 任务编辑弹窗
```

核心原则：

> **Core 继续复杂，API 给 UI 的形状必须简单。**

---

# 1. 不要让新前端依赖内部领域结构

V0.5 前端不需要知道：

- Scene 的内部存储方式；
- TaskPlacement；
- GenerationProfile ID；
- Provider ID；
- Job Snapshot；
- Result ID 细节；
- ContextLink 类型；
- VisualBeat 数据结构；
- Capability；
- Validator 细节。

这些对象仍然应该保留在 Core。

Frontend Adapter 负责把它们转换成 UI 真正需要的：

- 项目卡；
- 任务摘要；
- 任务编辑数据；
- 当前运行状态；
- 资产引用候选。

---

# 2. 前端需要的 4 类 Read Model

## 2.1 ProjectSummary

用于首页项目卡。

```ts
type ProjectSummary = {
  id: string;
  title: string;
  status: "idle" | "running" | "completed" | "failed";
  coverUrl: string | null;
  taskCount: number;
  assetCount: number;
  updatedAt: string;
};
```

### status 不由前端计算

推荐后端聚合规则：

```text
存在 Running / Queued Task 或 Job → running
否则项目有任务且全部已完成 → completed
否则存在需要显式处理的失败且无运行任务 → failed
否则 → idle
```

以后规则可变，但 UI 不应知道计算细节。

---

## 2.2 ProjectWorkspaceView

进入项目页后一次得到主要工作台数据。

```ts
type ProjectWorkspaceView = {
  project: {
    id: string;
    title: string;
  };
  tasks: TaskSummary[];
  runtime: ProjectRuntimeSummary;
};
```

不要求把所有 Asset / Result / Job 完整对象一次传入。

---

## 2.3 TaskSummary

列表模式、卡片模式、右侧只读栏共享同一个摘要对象。

```ts
type TaskSummary = {
  id: string;
  displayNumber: number;
  title: string;
  promptExcerpt: string;
  previewUrl: string | null;
  status: "idle" | "running" | "completed" | "failed";
  progress: number | null;
  assetCount: number;
  resultCount: number;
  durationSeconds: number;
  generationSummary: {
    resolution: string;
    quality: string;
  };
};
```

### promptExcerpt 推荐优先级

```text
Final Prompt
→ User Intent
→ Summary
→ 空字符串
```

### previewUrl 推荐优先级

```text
Primary Result Preview
→ 最新 Result Preview
→ Storyboard Frame
→ null
```

### resultCount

统计该 Task 所有历史 Job 下的有效 Result 数量。

UI 只显示：

`3 个生成版本`

不显示 Job ID / Result ID。

---

## 2.4 TaskEditorView

仅在用户双击 / 右键编辑任务时加载或提供。

```ts
type TaskEditorView = {
  id: string;
  displayNumber: number;
  title: string;
  userPrompt: string;
  aiEnhancedPrompt: string;
  durationSeconds: number;
  generation: {
    resolution: "720p" | "1080p" | "2K";
    quality: "快速" | "标准" | "高质量";
    mode: "全能参考" | "首尾帧";
    contextMode: "自动承接" | "尾帧承接" | "不承接";
  };
  assetBindings: TaskAssetRef[];
};
```

UI 不应该直接接收整个 `GenerationTask`。

后端 Adapter 将 UI 字段映射回：

- `finalPrompt`；
- `aiPrompt`；
- `plannedDurationSeconds`；
- `generationParams`；
- Context policy / Profile / Provider 参数。

---

# 3. ProjectRuntimeSummary

底部状态栏只需要一个非常小的运行摘要：

```ts
type ProjectRuntimeSummary = {
  activeTaskId: string | null;
  activeTaskTitle: string | null;
  state: "idle" | "queued" | "running" | "failed";
  progress: number | null;
};
```

前端渲染：

```text
● 当前运行：项目名 · 任务名：XXXX
```

无运行任务：

```text
当前没有正在运行的任务
```

不要让状态栏依赖完整 Queue 数据结构。

# 4. 推荐 API

统一前缀：

```text
/api/v1
```

## 4.1 项目首页

### 获取项目列表

```http
GET /api/v1/projects
```

响应：

```json
{
  "items": [
    {
      "id": "project-offworld",
      "title": "异星边境 初到基地",
      "status": "running",
      "coverUrl": "/media/project-offworld/cover.webp",
      "taskCount": 4,
      "assetCount": 6,
      "updatedAt": "2026-09-13T04:00:00Z"
    }
  ]
}
```

首页只调用这个接口，不加载所有任务详情。

### 新建项目

```http
POST /api/v1/projects
Content-Type: application/json

{
  "title": "异星边境 初到基地"
}
```

创建后返回 `ProjectSummary`。

### 重命名项目

```http
PATCH /api/v1/projects/{project_id}

{
  "title": "新的项目名"
}
```

# 5. 项目工作台 API

## 5.1 获取工作台

```http
GET /api/v1/projects/{project_id}/workspace
```

返回：

```json
{
  "project": {
    "id": "project-offworld",
    "title": "异星边境 初到基地"
  },
  "tasks": [
    {
      "id": "task-1",
      "displayNumber": 1,
      "title": "特瑞在荒漠驰骋",
      "promptExcerpt": "特瑞驾驶越野车穿过荒漠……",
      "previewUrl": "/media/task-1/preview.webp",
      "status": "completed",
      "progress": null,
      "assetCount": 4,
      "resultCount": 3,
      "durationSeconds": 6,
      "generationSummary": {
        "resolution": "1080P",
        "quality": "标准"
      }
    }
  ],
  "runtime": {
    "activeTaskId": "task-2",
    "activeTaskTitle": "越过断层台地",
    "state": "running",
    "progress": 43
  }
}
```

### 为什么使用 workspace 聚合接口

项目页首屏只需要：

- 项目名；
- 任务列表 / 卡片；
- 右侧摘要；
- 底部运行状态。

如果前端为了打开一个项目连续请求：

```text
project
scenes
tasks
jobs
results
assets
contexts
```

然后自己拼装，会再次把领域复杂度泄漏到前端。

`/workspace` 应作为专门的 Read Model 查询。

# 6. 任务编辑 API

## 6.1 打开已有任务

```http
GET /api/v1/projects/{project_id}/tasks/{task_id}/editor
```

返回 `TaskEditorView`。

如果 `/workspace` 已经缓存了当前任务所需编辑字段，也可先瞬时打开，再后台刷新，但最终接口边界仍建议独立。

## 6.2 保存已有任务

```http
PATCH /api/v1/projects/{project_id}/tasks/{task_id}
```

请求：

```json
{
  "userPrompt": "……",
  "aiEnhancedPrompt": "……",
  "durationSeconds": 6,
  "generation": {
    "resolution": "1080p",
    "quality": "标准",
    "mode": "全能参考",
    "contextMode": "自动承接"
  }
}
```

Adapter 再映射为 Core 需要的字段。

### 保存后必须执行

- 更新 Task 可变内容；
- 正确标记受影响 Context stale；
- 不修改历史 Job Snapshot；
- 不覆盖历史 Result；
- 返回新的 `TaskSummary` 或整个轻量 workspace delta。

---

# 7. 新建任务：不要在“打开编辑窗”时就落库

V0.5 的 UI 行为是：

```text
点击新建任务
→ 打开空白编辑弹窗
→ 用户填写
→ 保存
→ 真正创建任务
```

因此推荐：

```http
POST /api/v1/projects/{project_id}/tasks
```

只在用户点击“保存”时调用。

如果用户点击取消：

- 不产生 Task；
- 不产生 Placement；
- 不产生 Job；
- 不产生临时数据库垃圾记录。

请求体与编辑保存类似。

后端负责：

- 创建稳定 task_id；
- 生成展示序号；
- 插入当前 Story Order 尾部；
- 如果 Core 仍要求 Scene，放入默认 / 当前内部 Scene；
- 创建必要的 Context policy，但不要求前端知道 Scene / ContextLink。

---

# 8. V0.5 UI 与 Scene / TaskPlacement 的关系

新 UI 不再展示 Scene，但 **不要因此删除 Core 的 Scene / TaskPlacement**。

Frontend Adapter 负责把它们压平为：

```text
Task 1
Task 2
Task 3
...
```

排序规则仍可使用现有：

```text
Scene.orderKey
→ TaskPlacement.orderKey
```

前端只得到 `displayNumber = 1..N`。

这样未来如果重新引入剧本场次、分场、连续性逻辑，Core 数据不会被 UI 简化破坏。

---

# 9. Asset 适配

V0.5 不再提供默认一级“素材”页面，但任务编辑器的 `@` 引用仍需要 Asset 数据。

推荐接口：

```http
GET /api/v1/projects/{project_id}/assets?purpose=prompt-reference
```

返回轻量资产索引：

```ts
type AssetReferenceItem = {
  id: string;
  name: string;
  mediaType: "image" | "video" | "audio";
  category: "character" | "scene" | "prop" | "reference";
  previewUrl: string | null;
};
```

默认不要返回：

- 绝对文件路径；
- checksum；
- 内部存储元数据；
- Provider 专属字段。

项目业务仍然使用 `asset_id + project-relative path` 存储。

---

# 10. Result / 生成版本适配

项目页只显示：

```text
3 个生成版本
```

计算方式：Task 的所有历史 Job 对应 Result 数量。

如未来用户点击“生成版本”查看详情，再单独请求：

```http
GET /api/v1/projects/{project_id}/tasks/{task_id}/results
```

不要把完整历史 Result 全塞进 `/workspace`。

---

# 11. 实时进度更新

V0.5 项目页有：

- 任务状态；
- 当前运行任务；
- 后续移动端进度页需求。

推荐增加项目级 SSE：

```http
GET /api/v1/projects/{project_id}/events
Accept: text/event-stream
```

事件建议：

```text
task.status_changed
task.progress_changed
task.result_added
project.runtime_changed
project.summary_changed
```

示例：

```json
{
  "type": "task.progress_changed",
  "projectId": "project-offworld",
  "taskId": "task-2",
  "progress": 43,
  "status": "running"
}
```

### 为什么优先 SSE

当前需求主要是 Backend → UI 单向状态更新，不需要 WebSocket 的双向复杂度。

如果 SSE 暂时不做，可先用 1–2 秒轮询 `/workspace/runtime` 或 `/workspace`，但 Repository 接口应预留订阅能力，避免以后组件重写。

# 12. Frontend Repository / Gateway 层

真实后端接入时，React 组件不应直接 `fetch()`。

建议：

```ts
interface ProjectGateway {
  listProjects(): Promise<ProjectSummary[]>;
  createProject(input: { title: string }): Promise<ProjectSummary>;
  renameProject(projectId: string, title: string): Promise<ProjectSummary>;
  getWorkspace(projectId: string): Promise<ProjectWorkspaceView>;
  getTaskEditor(projectId: string, taskId: string): Promise<TaskEditorView>;
  createTask(projectId: string, input: SaveTaskInput): Promise<TaskSummary>;
  updateTask(projectId: string, taskId: string, input: SaveTaskInput): Promise<TaskSummary>;
  listPromptAssets(projectId: string): Promise<AssetReferenceItem[]>;
  subscribeProject(projectId: string, listener: (event: ProjectEvent) => void): () => void;
}
```

实现两套：

```text
MockProjectGateway
HttpProjectGateway
```

当前 V0.5 UI 先由 Mock 驱动；接后端时只替换 Gateway，不重写页面组件。

# 13. 前端状态归属

以下状态只属于 UI，本地保存即可，不进入 Core：

- 当前打开哪个项目；
- 列表 / 卡片模式；
- 当前选中哪个任务；
- 弹窗是否打开；
- 列表滚动位置。

其中 `列表 / 卡片模式` 可写到本地用户偏好（localStorage / app settings）。

以下状态必须来自后端：

- 项目名称；
- 项目状态；
- Task 数据；
- 资产数量；
- Result 数量；
- 当前运行 Job / Task；
- Progress；
- Preview；
- 生成参数；
- Prompt。

---

# 14. 数据库建议

V0.5 UI 本身不要求重做 Core 数据表。

至少需要稳定持久化：

```text
projects
scenes
generation_tasks
task_placements
assets
task_asset_bindings
generation_context_links
jobs
results
```

Frontend Adapter 可以通过 SQL / Repository 聚合得到 ProjectSummary 和 TaskSummary。

如果性能需要，可增加 read-model cache，但第一版不要为了 UI 新建一套重复的业务真相表。

# 15. 项目封面

首页项目卡需要 cover。

建议 Project metadata 增加：

```text
cover_asset_id: nullable
```

读取优先级：

```text
显式项目封面
→ 第一个 Primary Result Preview
→ 第一个 Storyboard Frame
→ 默认占位
```

前端只接收最终 `coverUrl`。

# 16. 错误与并发

## 16.1 保存任务

如果保存冲突，API 返回 409，并提供当前 `revision`。

推荐 Task 增加乐观锁版本：

```text
revision: integer
```

`TaskEditorView` 返回 revision，PATCH 时携带：

```json
{
  "revision": 12,
  "userPrompt": "..."
}
```

避免后台进程 / 多窗口静默覆盖编辑。

## 16.2 用户可见错误

Backend 可返回稳定 error code：

```text
PROJECT_NOT_FOUND
TASK_NOT_FOUND
TASK_CONFLICT
ASSET_NOT_FOUND
GENERATION_SERVICE_OFFLINE
CONTEXT_STALE
```

Frontend 再翻译成中文，不直接显示 Python Exception / Provider 原始错误。

# 17. 建议后端模块结构

当前 backend 很轻，可以从下面结构开始：

```text
backend/shotmill/
├─ app.py
├─ api/
│  ├─ projects.py
│  ├─ tasks.py
│  ├─ assets.py
│  └─ events.py
├─ application/
│  ├─ project_service.py
│  ├─ task_service.py
│  └─ workspace_query.py
├─ domain/
│  └─ ... 原 Core 对象
├─ repositories/
│  ├─ project_repository.py
│  ├─ task_repository.py
│  └─ ...
├─ adapters/
│  ├─ frontend_models.py
│  └─ frontend_mapper.py
└─ providers/
   └─ ...
```

关键点：

`workspace_query.py` / `frontend_mapper.py` 是 V0.5 新前端最重要的隔离层。

# 18. 实施顺序

## Phase A：只读接入

1. Project persistence；
2. `GET /projects`；
3. `GET /projects/{id}/workspace`；
4. 前端替换首页 / 工作台 Mock 查询；
5. SSE 或轮询更新运行状态。

## Phase B：写入

1. `POST /projects`；
2. `PATCH /projects/{id}`；
3. `GET task/editor`；
4. `POST task`；
5. `PATCH task`；
6. 资产引用索引。

## Phase C：执行与结果

1. 生成命令接入 Queue；
2. Job Progress → Project Event；
3. Result 创建；
4. TaskSummary / ProjectSummary 自动更新；
5. 移动端进度页复用相同 Runtime / Event API。

# 19. Contract Tests

至少增加以下 API Contract Test：

- `GET /projects` 不泄漏 Provider / Job / Context 内部字段；
- Project status 聚合正确；
- Workspace Task 顺序正确；
- `assetCount` 正确；
- `resultCount` 正确；
- Preview fallback 正确；
- 新建任务取消不落库；
- 保存现有任务不修改历史 Job Snapshot；
- Primary Result 变化仍触发 Context stale；
- 运行进度事件能更新对应 Task；
- 项目重命名不影响 project_id；
- 绝对文件路径不出现在 Frontend DTO。

# 20. 最终边界

V0.5 新 UI 是一个更简单的产品视图，不意味着 Core 也要退化成简单 CRUD。

正确关系是：

```text
复杂 Core
   ↓
稳定 Application Service
   ↓
面向 V0.5 的 Frontend Read / Command Adapter
   ↓
极简 UI
```

不要反过来为了配合两张页面，把：

- Job；
- Result 历史；
- Context；
- Scene；
- TaskPlacement；
- Provider Capability；

从 Core 删除。

**前端变简单，应通过 Adapter 隔离复杂度，而不是牺牲后端模型能力。**
