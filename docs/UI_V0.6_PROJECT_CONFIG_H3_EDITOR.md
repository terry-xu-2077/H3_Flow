> 日期：2026-09-13  
> 状态：覆盖 V0.5 中对应的工作台顶部、项目配置、提示词编辑与结果预览规则。

## 1. 项目工作台顶部

### 1.1 左侧

旧的 `Terry导演工作台` 文字按钮不再承担返回行为。

项目页左上固定为：

```text
[🏠] 返回首页
```

规则：

- 明确表达返回项目首页；
- 必须带房子图标；
- 不把产品标题伪装成导航按钮。

### 1.2 中间

继续显示：

```text
[文件夹] 项目标题 ✎
```

铅笔可做快捷重命名。

### 1.3 右侧

顺序：

```text
[项目配置]   表格 / 卡片
```

项目配置是项目级设置的唯一明确入口，不能塞进任务编辑器。

# 2. 任务工具栏

`＋ 新建任务 / N 个任务` 工具栏必须在 **表格视图和卡片视图中都存在**。

卡片模式可以继续保留“新建任务卡”，但顶部工具栏不得消失。

---

# 3. 右侧结果预览

右侧栏仍然只读。

如果当前任务存在可播放 Result：

- 预览区显示结果缩略图；
- 显示轻量播放提示；
- 点击缩略图打开独立播放弹窗；
- 播放弹窗使用真实 `videoUrl`；
- 不在右栏内直接展开视频播放器，避免右栏变成复杂操作区。

如果没有 Result：

- 继续显示 Storyboard Frame / 占位预览；
- 不伪造可播放行为。

# 4. 用户提示词 / AI 增强提示词

任务编辑器中有两个独立维度：

```text
提示词来源： [用户] [AI 增强]
显示方式：   [可视化] [文本]
```

两者必须完全解耦。

## 4.1 提示词来源

沿用上一轮规则：

- 当前选中“用户” → 任务使用用户提示词；
- 当前选中“AI 增强” → 任务使用 AI 增强提示词；
- 保存 `promptSource = user | ai`；
- 两份文本独立保存，切换来源不互相覆盖。

## 4.2 显示方式

无论用户提示词还是 AI 增强提示词，都必须拥有：

- `可视化`；
- `文本`。

并且两边各自记忆自己的显示方式：

```ts
userPromptViewMode: "visual" | "text"
aiPromptViewMode: "visual" | "text"
```

这两个字段属于编辑体验偏好，不影响最终提示词内容。

# 5. H3 可视化编辑器

可视化模式参考现有 ComfyUI TerryXu H3 提示词编辑器，不新定义另一套 H3 语法。

第一阶段至少可视化以下内容：

- `subject_definitions:` 等 H3 区块标题；
- `<Subject N>`；
- `<Picture N>`；
- `<Video N>`；
- `<Audio N>`；
- `[Shot N]`；
- `(S1)` 等说话人；
- `<d>[Language] ...</d>` 对白；
- `[00:00]` 时间标签；
- `<scenetrans>` / `<cutoff>`；
- reference / retention 类标签；
- H3 任务标签；
- 已知 camera command，并以中文可读名称显示。

## 5.1 素材引用

当 `<Subject N>` / `<Picture N>` / `<Video N>` / `<Audio N>` 能解析到当前任务资产：

- 图片 / 视频优先显示缩略图；
- 音频显示轻量音频标识；
- 显示资产名，而不是只显示原始协议标签；
- 原始 H3 标签仍作为序列化值保留。

## 5.2 文本模式

文本模式始终显示原始 H3 Prompt。

可视化模式和文本模式必须是 **同一份字符串数据的两种编辑视图**，禁止维护两份互相漂移的内容。

## 5.3 对白

可视化模式中的 `<d>[Language] ...</d>` 应表现为：

- 语言选择；
- 对白正文；
- 修改后仍序列化回标准 H3 标签。

## 5.4 `@` 引用

文本模式继续支持输入 `@` 调出任务资产。

可视化模式也应逐步做到与 ComfyUI H3 编辑器一致的素材插入体验；不得因为采用可视化模式而改变最终引用格式。

# 6. 项目配置窗口

项目配置是独立浮窗，当前只暴露两个一级分类：

```text
项目信息
资产管理
```

禁止因为“以后可能还有配置”就提前堆出一排空参数。

## 6.1 项目信息

包含：

### 项目标题

- 可修改；
- 与工作台中间显示的项目标题同步；
- 顶部铅笔仍可作为快捷重命名。

### 项目简介

用于说明：

- 世界观；
- 题材；
- 主要角色关系；
- 视觉基调；
- 项目级创作限制。

它不是任务提示词本身。

### AI 背景开关

```text
☑ AI 增强时使用项目简介作为背景
```

启用后：

- 项目简介作为 AI Prompt Enhancer 的项目级 Context；
- 不自动拼进用户提示词；
- 不改变任务最终 Prompt 的可见文本；
- Prompt Provider / Skill 可以使用它理解项目背景。

关闭后：

- AI 增强请求不携带项目简介。

# 7. 资产管理

项目配置中的“资产管理”管理项目级 Asset Library。

当前 UI 至少包含：

- 资产数量；
- 图片 / 视频 / 音频；
- 资产名称；
- 资产分类；
- 缩略图；
- 添加资产；
- 移除资产。

后续可以继续增加：

- 重命名；
- 分类修改；
- 标签；
- 使用关系；
- 资产详情。

但必须按需求逐步出现，不得一次堆满主窗口。

---

# 8. 项目级配置的扩展原则

未来新增项目级配置时，先判断它属于：

1. 项目信息；
2. 资产管理；
3. 确实需要的新分类。

只有第三种情况稳定出现多项需求时，才新增项目配置分类。

原则仍然是：

> **先合并、再隐藏、最后才新增一级分类。**

# 9. 回归验收

每次修改必须确认：

- [ ] 左上是“返回首页”并带房子图标；
- [ ] 右上存在项目配置按钮；
- [ ] 表格 / 卡片都有顶部“新建任务”工具栏；
- [ ] 有结果的右侧缩略图可打开播放弹窗；
- [ ] 用户 Prompt 有可视化 / 文本；
- [ ] AI Prompt 有可视化 / 文本；
- [ ] 用户 / AI 标签仍决定真正使用哪份提示词；
- [ ] 两种提示词各自记忆显示模式；
- [ ] 项目配置可编辑标题与简介；
- [ ] 可选择是否把项目简介用于 AI 增强；
- [ ] 项目配置包含资产管理；
- [ ] 未重新出现参数墙。
