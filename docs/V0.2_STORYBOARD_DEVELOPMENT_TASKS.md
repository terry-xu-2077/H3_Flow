# 1. V0.2 核心模型

## 1.1 Shot 与 Task 不等价

Storyboard 的基本创作单位是 `Shot`。

视频生成的基本执行单位是 `GenerationTask`。

两者不是固定一一对应。

当前 MiniMax-H3 工作方式允许一次最长约 15 秒的 Task 在 Prompt 中描述多个分镜，因此常见情况是：

```text
Storyboard Order
Shot 001 → Shot 002 → Shot 003 → Shot 004 → Shot 005

Generation Grouping
Task A = Shot 001 + Shot 002 + Shot 003
Task B = Shot 004 + Shot 005
```

为了兼容未来长镜头续接，也不能假设一个 Shot 永远只会被一个 Task 覆盖。

因此必须严格区分：

```text
1. Story Order
2. Generation Grouping
3. Generation Context
```

### Story Order

```text
Shot 001 → Shot 002 → Shot 003
```

表示叙事 / 分镜顺序。

### Generation Grouping

```text
Task A = [Shot 001, Shot 002]
Task B = [Shot 003]
```

表示一次 Provider 调用覆盖哪些 Storyboard Shot。

### Generation Context

```text
Task A ── Visual / Audio / Latent / Semantic ──> Task B
```

表示 Task 之间的生成依赖与续接关系。

三者不得混为同一个数组、同一个排序字段或同一个 Link。

# 2. V0.2 最终必须跑通的闭环

V0.2 完成后，在 `/dev/ui` + Mock Repository 中至少必须完整跑通：

```text
打开项目
    ↓
进入 Storyboard Workspace
    ↓
创建 / 选择 Scene
    ↓
粘贴剧本或手动新建 Shot
    ↓
形成 Storyboard Shots
    ↓
调整 Story Order
    ↓
设置画面、镜头语言、资产、创作意图
    ↓
选择连续 Shot 创建 / 调整 Generation Task Group
    ↓
Prompt AI 根据 Task 内多个 Shot 编译 Prompt
    ↓
人工修改 Final Prompt
    ↓
Generation Task Ready
    ↓
Task 加入 Queue
    ↓
Mock Result 返回
    ↓
Result 映射回 Task 覆盖的多个 Shot
    ↓
设置 Primary Result
    ↓
检查下游 Task Context
    ↓
Story Reel 按 Story Order 预览
```

同时支持：

```text
Script → AI Shot Proposal → 人工合并 / 拆分 / 调整 → 确认进入 Storyboard
```

以及：

```text
Storyboard Reorder
    ↓
Task Grouping Review
    ↓
Continuity / Context Check
    ↓
必要时 Context Stale
```

V0.2 的完成标准不是“有一个分镜页面”，而是用户可以在 Storyboard 中完成从拆镜到任务分组再到生成结果回看的一整套工作方式。

# 3. 产品边界

Storyboard 是创作与素材生产视图，不是 NLE。

V0.2 明确不做：

- 视频剪辑时间线。
- 多轨视频 / 音频编辑。
- Clip Trim / Razor / Ripple Edit。
- 转场编辑。
- 字幕 / 配音时间线。
- 音量包络 / 混音。
- 关键帧动画编辑。
- 视频特效。
- 自动成片。

可以做：

- Scene / Shot 顺序。
- Shot Planned Duration。
- Storyboard Frame。
- Generation Task Grouping。
- Task 边界。
- Task Planned Duration。
- Primary Result 视频预览。
- Result → Shot Span 映射。
- Story Reel / Animatic Preview。
- Story Continuity。
- Task Generation Context。

**Task Grouping 不是剪辑时间线。Story Reel 也不是剪辑时间线。**

# 5. 开发原则

## 5.1 Mock-first

```text
Domain Contract
↓
/dev/ui + Mock Storyboard / Task Grouping
↓
人工打磨操作手感
↓
Playwright / Visual Regression
↓
真实 Core / SQLite / Provider 接入
```

## 5.2 Capability Driven

H3 Profile 当前可以声明：

```text
multi_shot_prompt = true
max_duration ≈ 15s
```

但 Core 不得写：

```text
if H3: 15s
```

未来其他模型可能：

- 只允许单镜头。
- 支持更长时长。
- 支持多镜头但不支持 continuation。
- 支持一个长镜头跨 Task 续接。

UI、Validator、Grouping Suggestion 都依据 Generation Profile Capability 工作。

## 5.3 历史不可变

Storyboard、Task Grouping 可以继续修改，但已提交 Job 必须保存当时：

- Shot 列表与顺序。
- Final Prompt。
- Assets。
- Profile / Params。
- Context 来源。

历史 Job / Result 不得因为 Storyboard 后续调整被静默重写。

# Phase S3 — Generation Task Bands / Grouping

这是 V0.2 新的核心交互。

## S3.1 Task Band

在连续 Shot 上方显示轻量 Task Band：

```text
Task A · MiniMax-H3 · 12s · READY
┌────────────────────────────────────────────┐
│ [Shot 001] [Shot 002] [Shot 003]          │
└────────────────────────────────────────────┘
```

要求：

- 不把 Task 再画成一套巨大卡片。
- Task Band 边界清晰。
- 显示 Profile、计划总时长、Task 状态。
- 支持选中 Task Band。

## S3.2 Group Selected Shots

用户多选相邻 Shot 后可：

```text
创建生成任务
```

生成一个 Task + TaskShotBindings。

对于不连续选择：

- 默认禁止直接组成同一个常规 Task；
- 或明确要求用户确认特殊分组。

V0.2 默认优先连续 Shot。

## S3.3 Split Task Here

在 Task 内 Shot 边界可：

```text
在此拆分 Task
```

例如：

```text
Task A = 001 + 002 + 003 + 004
```

拆为：

```text
Task A = 001 + 002
Task B = 003 + 004
```

## S3.4 Merge Adjacent Tasks

支持合并相邻 Draft Task。

合并前检查：

- Generation Profile 是否兼容。
- 计划总时长是否超过 Profile Capability。
- 是否已有不可变 Job。

已有 Job 的 Task 不直接破坏历史；应创建新的 grouping revision / new Task。

## S3.5 Grouping Suggestion

Mock Prompt Provider 可根据：

- planned duration。
- Scene 边界。
- continuity。
- Generation Profile max_duration。
- multi-shot capability。

给出 Task Grouping Proposal。

AI 建议必须人工确认。

### Gate S3

用户可以非常直观地把 Storyboard Shot 组合成适合当前 Generation Profile 的生成任务。

# 8. V0.2 完成定义

最终体验应达到：

```text
用户进入 Scene
↓
看到真正的视觉 Storyboard Shots
↓
快速调整 Shot 顺序和创作信息
↓
选择若干连续 Shot
↓
组成一次 Generation Task
↓
根据当前 Profile 时长 / 能力检查任务是否合法
↓
AI 将多个 Shot 编译成一次生成 Prompt
↓
用户确认 Final Prompt
↓
Task 批量生成
↓
一个 Result 映射回多个 Storyboard Shot
↓
Task 与下一个 Task 保持 Context
↓
用户按 Story Order 查看 Story Reel
```

并且整个过程中：

- **Shot 不等于 Task。**
- **Task 可以包含多个 Shot。**
- **Core 不限制 Shot 只能属于一个历史 Task。**
- **Story Order、Task Grouping、Generation Context 三者独立。**
- **Result 不假设一一对应 Shot。**
- **Ready / Queue / Running 等执行状态属于 Task。**
- **H3 15 秒与多分镜能力通过 Generation Profile / Capability 表达，不写死 Core。**
- 不把 Storyboard 做成 NLE。
- 不破坏 V0.1 已验证的 Overlay、Prompt Composer Final Prompt 保护和 `@` Asset Editor 行为。
