> 状态：V0.2 Freeze 验收通过（2026-09-12）
> 版本目标：V0.2 — Storyboard-style Task Workspace
> 最后修订：2026-09-12

本文档是 V0.2 的主执行清单。

## 关键产品定义

ShotMill 所说的 Storyboard 是一种**分镜式、画面化、按故事顺序排列的 Task 交互方式**，不是专业分镜制作工具。

**每一张 Storyboard 卡片都是一个 `GenerationTask`。**

Task 不硬绑定为一个 Shot。一张卡可以生成单镜头，也可以在同一次 Prompt / Provider 调用中描述多个镜头或视觉节拍。V0.2 不再把 Shot Card 与 Task Band 作为两套并列主对象。

涉及 Storyboard / Task / Job / Result / Context 时，必须先读 `STORYBOARD_TASK_MODEL.md`。

# 1. V0.2 核心模型

## 1.1 Card 与 Task 等价

```text
1 Storyboard Card = 1 GenerationTask
```

卡片显示 Task 的代表画面、标题、故事摘要、计划时长、视觉节拍数量、资产摘要、Profile 和运行状态。

以下表达是错误的：

```text
1 Card = 1 Shot
Shot Cards + 独立 Task Bands
先建立完整 Shot 清单，再把 Shot 组合成 Task
```

## 1.2 Task 可以包含多镜头描述

```text
Task A · 15s
├─ 0-4s   远景建立雨夜码头
├─ 4-9s   中近景人物停在门前
└─ 9-15s  特写推门
```

这些内容以可选 `TaskVisualBeat[]` 或 Prompt 文本存在于 Task 内部，不拥有独立队列、Job、Result 或卡片身份。

## 1.3 三层关系独立

```text
Story Order          Task A → Task B → Task C
Task Content         Task A = 1..N Visual Beats
Generation Context   Task A ── Visual / Audio / Semantic ──> Task B
```

卡片重排只修改 `TaskStoryboardPlacement`，不得静默修改 Context、Job 或 Result。

# 2. V0.2 最终闭环

在 `/dev/ui` + Mock Repository 中必须跑通：

```text
打开项目
    ↓
进入 Storyboard-style Task Workspace
    ↓
创建 / 选择 Scene
    ↓
粘贴剧本或手动新建 Task Card
    ↓
确认 AI Task Proposal（每个 Task 可含 1..N 视觉节拍）
    ↓
调整 Task Story Order / Scene placement
    ↓
设置代表画面、资产、创作意图与 Generation Profile
    ↓
Prompt AI 编译整个 Task 的 Prompt
    ↓
人工修改 Final Prompt
    ↓
Task Ready → Queue → Mock Result
    ↓
审核并设置 Task Primary Result
    ↓
检查下游 Task Context / Context Stale
    ↓
Story Reel 按 Task Story Order 预览
```

完成标准不是“出现一个分镜页面”，而是 Task 从故事规划到生成回看的主流程可在分镜式工作区完成。

# 3. 产品边界

V0.2 可以做：

- Scene 分区与排序；
- Task Card 创建、复制、删除、排序与跨 Scene 移动；
- Task 代表帧；
- Task 内多镜头 / 多视觉节拍描述；
- Task 计划时长、资产、Profile、Prompt 与 Context；
- Job / Result 历史与 Primary Result；
- 按 Task Story Order 的 Story Reel。

V0.2 明确不做：

- 独立 Shot Card + Task Band 双层编辑；
- 专业 Shot 列表、镜号管理和镜头级生产状态；
- 视频剪辑时间线、多轨音视频、Trim、Razor、Ripple Edit；
- 转场、字幕、混音、关键帧或特效编辑；
- 自动成片。

Task 内视觉节拍不是 NLE Clip，也不是新的一级业务对象。

# 5. 开发原则

## 5.1 Mock-first

```text
Domain Contract
↓
/dev/ui + Mock Task Board
↓
人工打磨操作手感
↓
Playwright / Visual Regression
↓
真实 Core / SQLite / Provider 接入
```

## 5.2 Capability Driven

多镜头 Prompt 与最大时长由 Generation Profile Capability 声明：

```text
multi_shot_prompt = true
max_duration_seconds = 15
continuation = true | false
```

Core 不得写死 H3 或 15 秒。专属行为只存在于 Skill、Adapter、Profile 或 Validator。

## 5.3 历史不可变

Task 内容与 Story Order 可以继续修改，但已提交 Job 必须保存当时的 Task 内容、Final Prompt、Assets、Profile / Params 与 Context 快照。历史 Job / Result 不得被后续编辑静默重写。

# Phase S0 — Task-first Domain Contract

目标：先让领域模型符合“一张卡就是一个 Task”。

## S0.1 Scene

```text
Scene { id, number, title, summary, order_key, location, time_of_day, notes }
```

Scene ID 稳定，Number 可重算；Scene 可为空、折叠、排序。

## S0.2 TaskStoryboardPlacement

```text
TaskStoryboardPlacement { task_id, scene_id, order_key }
```

它只表达 Task Card 当前在故事板中的位置。

## S0.3 GenerationTask

至少包含：

```text
id / number / title / summary
script_source / user_intent
storyboard_frame / visual_beats[] / asset_bindings[]
generation_profile_id / generation_params
ai_prompt / final_prompt / prompt_revisions[]
context_link_ids[] / state / job_ids[] / primary_result_id?
```

## S0.4 TaskVisualBeat

```text
TaskVisualBeat
├─ id
├─ label
├─ description
├─ planned_start? / planned_end?
├─ shot_size? / camera_movement?
└─ notes?
```

Beat 是 Task 内可选描述，不是独立卡片、Queue item、Job 或 Result owner。

## S0.5 Job / Result / Context

- Job 保存 Task 的不可变提交快照。
- Result 属于 Job，并保留历史。
- Primary Result 属于 Task。
- Generation Context Link 连接 Task，独立于 Story Order。

### Gate S0

- `1 Card = 1 GenerationTask` 已落入 TypeScript Domain 与 Mock。
- 一个 Task 可含 1..N 视觉节拍。
- 不要求一级 `StoryboardShot`、`TaskShotBinding` 或 `ResultShotSpan`。
- Story Order 与 Generation Context 独立。
- Job / Result 历史不可变。

# Phase S1 — Storyboard Workspace Shell

## S1.1 默认入口

`/dev/ui` 默认进入“分镜”，旧任务页能力合并或迁移到新工作区，不再作为另一套对象模型长期并存。

## S1.2 三栏布局

```text
┌──────────────┬──────────────────────────────────┬────────────────┐
│ Scene        │ Storyboard-style Task Cards      │ Inspector      │
│ Navigator    │                                  │                │
└──────────────┴──────────────────────────────────┴────────────────┘
```

验收：

- 1366×768 可用；1600×900 / 1920×1080 为主；
- 中央 Task Board 空间优先；
- 左右栏可折叠；
- 页面级无横向溢出。

## S1.3 Scene Section

示例：

```text
Scene 01 · 仓库外 · 夜
11 Tasks · 143s planned · 3 Running · 2 Needs Attention
```

### Gate S1

30+ Task Cards、多个 Scene 和多镜头 Task 混合时仍能清楚扫描；用户不会误以为卡片是一条独立 Shot。

# Phase S2 — Storyboard Task Card

Task Card 是中央工作区唯一主要卡片对象：

```text
┌────────────────────────────┐
│      Storyboard Frame      │
├────────────────────────────┤
│ Task A · READY · H3 · 15s  │
│ 抵达仓库并推门             │
│ 3 个视觉节拍 · 3 项资产    │
└────────────────────────────┘
```

默认展示：

- Task Number / Title；
- Storyboard Frame / Primary Result Preview；
- Task 状态与稳定进度区域；
- 计划时长与 Profile；
- 视觉节拍数量（单镜头或多镜头提示）；
- 资产摘要与 Context Stale / Failed 警告。

长文本截断且可查看全文；状态切换不造成卡片跳动；技术参数不塞满卡片。

### Gate S2

用户一眼知道“这是一张生成任务卡”，并能识别它是单镜头还是多镜头描述。

---

# Phase S3 — Task Selection / Create / Duplicate / Delete

支持：

- 单击选择并更新 Task Inspector；
- 双击进入 Task Composer；
- Ctrl/Cmd 多选、Shift 范围选择；
- Insert Before / After；
- New Next Task；
- Duplicate / Duplicate Selected；
- Delete 与可恢复确认；
- 多选 Batch Bar。

复制 Task 默认不复制 Job、Result、运行状态或 Context 依赖；是否继承 Profile / Assets 必须清楚表达。

### Gate S3

大量 Task 下的选择、创建、复制和删除行为稳定且可预测。

---

# Phase S4 — Story Order / Scene / Drag

支持 Scene 内排序与跨 Scene 移动 Task Card。

拖动后：

- Task ID 不变；
- 更新 `TaskStoryboardPlacement`；
- 展示编号可重算；
- Job / Result 不变；
- Context Link 不静默改写；
- 若叙事邻接改变影响上下文语义，标记 Context Review / Stale。

键盘至少支持 Ctrl/Cmd+C、Ctrl/Cmd+V、Ctrl/Cmd+D、Delete、Enter、Escape、Arrow Keys。

### Gate S4

调整卡片故事顺序不会偷偷改变任务历史或生成依赖。

显示 Scene 元信息、Task 数量、计划总时长与状态汇总。

## S5.3 Batch Inspector

多选 Task 时提供批量移动 Scene、Profile、资产、Queue 与删除等明确操作。

### Gate S5

快速属性在 Inspector 完成，完整 Prompt 与高级参数进入 Task Composer，职责清楚。

# Phase S6 — Script → Task Cards

支持粘贴大段剧本、手动选段创建 Task、Mock AI Task Proposal。

```text
TaskProposal
├─ temp_id
├─ script_excerpt
├─ title / summary / user_intent
├─ visual_beats[]
├─ planned_duration
├─ suggested_assets[]
├─ suggested_profile
└─ notes
```

用户可修改、删除、排序、合并、拆分 Proposal 和选择 Scene；显式确认后才创建正式 GenerationTask。

这里的“拆分”是把剧本生产意图拆成多个 Task Proposal；每个 Task Proposal 内仍可包含多镜头视觉节拍。

### Gate S6

用户可以从剧本得到合理 Task Cards，并能在确认前控制每个 Task 的边界和内部多镜头描述。

---

# Phase S7 — Asset Library / Task Binding

实现 Image / Video / Audio、Character / Scene / Prop / Reference 分类、Search / Tags、Preview、Multi-select、Confirm / Cancel。

资产直接绑定到 Task，并保留 `asset_id` 与 project-relative path；Prompt 编译记录解析后的资产快照。`@` Asset Editor 必须继续可用。

### Gate S7

单镜头与多镜头 Task 都能明确引用资产，且 Prompt Composer 能追踪素材来源。

---

# Phase S8 — Multi-shot Task Composer / Prompt

现有 V0.1 Task Composer 升级为完整 Generation Task Composer。

## S8.1 Task Visual Beat Strip

对含多镜头描述的 Task 显示可选 Beat Strip：

```text
[0-4s 建立] [4-9s 停顿] [9-15s 推门]
```

它只辅助编辑整个 Task 的 Prompt，不创建独立 Storyboard Card。

## S8.2 PromptRequest

至少包含 Task 内容、Visual Beats、Assets、Previous Task Context、Next Story Context 与 Target Generation Profile。

## S8.3 Prompt 与 Final Prompt

- Prompt Skill 决定 H3 或未来模型语法；
- AI Prompt 不自动覆盖人工 Final Prompt；
- Revision 独立；
- `@` Asset Editor 与光标 / 焦点行为不退化。

### Gate S8

Task Composer 能编辑一张 Task Card 内的单镜头或多镜头生成意图，且人工 Final Prompt 始终受保护。

---

# Phase S9 — Ready / Queue / Context

Ready Validation 检查 Final Prompt、Assets、Profile Capability、Task 计划时长、Visual Beats timing、Context 与 Provider 可用性。

Generation Context 支持 Semantic、Visual、Audio、Latent / Native、Fallback。至少在上游 Primary Result 改变、Task 内容改变、Story Order 影响邻接语义或 Context 来源改变时标记 Stale。

提供保持现有结果、重编 Prompt、更新 Context、从该 Task 向后重新生成等明确操作。

### Gate S9

用户清楚区分卡片故事顺序、Task 内部多镜头内容和 Task 间生成续接。

---

# Phase S10 — Result / Review / Primary

- Result 属于 Job / Task；重新生成不得覆盖历史 Result；
- 多镜头 Task 的 Result 仍作为完整 Task Result 审核；
- 支持 Preview、Approve / Reject、Set Primary、Regenerate、Open History；
- Primary Result 改变正确传播 Context Stale；
- Task Card 可使用 Primary Result preview 作为代表画面。

V0.2 不强制 ResultShotSpan。未来如需镜头级时间提示，只作为 Task Result 的可选 metadata。

### Gate S10

每张 Task Card 能追踪自己的不可变生成历史，并清楚显示当前 Primary Result。

---

# Phase S11 — Story Reel

Story Reel 按 Task Story Order 播放：

```text
Primary Task Result
↓
Task Storyboard Frame
↓
Placeholder
```

仅提供 Play / Pause、Previous / Next Task、Jump to Task、Current Task 与 Planned Duration，禁止 NLE 控件。

### Gate S11

用户能按卡片故事顺序感受生成素材节奏，包括一张 Task Result 内含多个镜头的情况。


# 8. V0.2 完成定义

只有以下全部成立才算完成：

- **Storyboard 是 Task 的分镜式交互工作区，不是独立 Shot 工具。**
- **1 Storyboard Card = 1 GenerationTask。**
- **Task 不硬绑定为一个 Shot，可包含 1..N 视觉节拍。**
- **Story Order、Task Content、Generation Context 三者独立。**
- **Task 是可变意图；Job 与 Result 保持不可变历史。**
- **Ready / Queue / Running 等执行状态属于 Task。**
- **H3 能力通过 Generation Profile / Capability 表达，不写死 Core。**
- **不把 Storyboard 做成 NLE。**
- **不破坏 V0.1 Overlay、Prompt Composer Final Prompt 保护和 `@` Asset Editor。**
