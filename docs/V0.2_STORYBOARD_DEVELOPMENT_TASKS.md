# ShotMill V0.2 Storyboard 开发任务

> 状态：开发规划基线  
> 版本目标：V0.2 — Storyboard Workspace  
> 仓库：https://github.com/terry-xu-2077/TerryShotMill  
> 前置版本：`V0.1_DEVELOPMENT_TASKS.md`  
> 关联文档：`ShotMill_产品与架构规划.md`、`UI_UX_SPEC.md`、`TEST_STRATEGY.md`

本文档用于把 ShotMill 下一阶段拆成可直接交给 Codex 以“目标”方式执行的开发任务。

V0.2 的核心目标不是在现有“任务列表”旁边再增加一个分镜页面，而是把 ShotMill 的日常创作入口正式升级为一个完整、连续、高效的 **Storyboard Workspace**。

用户面对的主要概念从“Task”转变为：

```text
Project
  ↓
Scene
  ↓
Shot
  ↓
Storyboard
```

`Task` 仍然是 ShotMill Core 内部的重要业务概念；UI 中的 `Shot` 与生成 Task 建立稳定映射，但不得为了 Storyboard 把 Core 写死为某个视频模型、Prompt 格式或 Provider。

---

# 1. V0.2 最终必须跑通的 Storyboard 闭环

V0.2 完成后，在 `/dev/ui` + Mock 数据环境中至少必须完整跑通：

```text
打开项目
    ↓
进入 Storyboard Workspace
    ↓
创建 / 选择 Scene
    ↓
粘贴剧本或手动新建 Shot
    ↓
形成一组 Storyboard Shot
    ↓
拖动调整 Shot 顺序 / 跨 Scene 移动
    ↓
为 Shot 设置画面、镜头语言、资产和创作意图
    ↓
检查 Previous / Next 与 Context 连续性
    ↓
生成 / 编辑 Final Prompt
    ↓
Shot 进入 Ready
    ↓
多选 Shot / 整 Scene 加入 Queue
    ↓
Mock Generation Result 返回
    ↓
设为 Primary Result
    ↓
Storyboard Frame 自动更新
    ↓
Story Reel 按顺序预览整个 Storyboard
```

同时必须支持以下编辑闭环：

```text
Script → AI 拆镜候选 → 人工合并 / 拆分 / 调整 → 确认进入 Storyboard
```

以及：

```text
Story Order 改变
    ↓
Continuity / Context 检查
    ↓
必要时标记 Context Stale
```

V0.2 的判断标准不是“页面已经画出来”，而是用户可以围绕 Storyboard 连续工作，不必频繁跳页面或重新理解 Task 工程概念。

# 2. V0.2 产品边界

Storyboard 是 ShotMill 的创作与素材生产视图，不是 NLE。

V0.2 明确不做：

- 视频剪辑时间线。
- 多轨视频 / 音频编辑。
- Clip Trim / Razor / Ripple Edit。
- 转场编辑。
- 字幕时间线。
- 配音时间线。
- 音量包络 / 音频混音。
- 关键帧动画编辑。
- 视频特效。
- 自动成片。
- 成片导出时间线。

可以做：

- Scene / Shot 顺序。
- Planned Duration。
- Storyboard Frame。
- Primary Result 视频预览。
- Story Reel / Animatic Preview。
- Previous / Next Shot。
- Story Continuity。
- Generation Context。

**Story Reel 只是按 Story Order 预览分镜与已有结果，不允许演变为剪辑时间线。**

# 4. V0.2 开发原则

## 4.1 继续坚持 Mock-first

本版本继续遵守：

```text
Domain Contract
    ↓
/dev/ui + Mock Storyboard
    ↓
人工打磨 Storyboard 手感
    ↓
Playwright / Visual Regression 固化
    ↓
真实 Core / SQLite / Provider 接入
```

V0.2 的主交付是：

- 正确的 Storyboard 产品结构。
- 正确的 Scene / Shot 数据协议。
- 完整可交互 Mock 工作流。
- 可回归的 UI 行为测试。
- 为后续真实持久化和 Provider 接入准备稳定 Contract。

V0.2 不要求完成完整真实生成 Core；真实 SQLite、Scheduler、ComfyUI Provider 的大规模接入继续放在后续阶段。

## 4.2 不允许把 Storyboard 写成 H3 专用界面

Storyboard 中允许出现：

- Shot Size。
- Camera Movement。
- Story Beat。
- Planned Duration。
- Character / Scene / Prop。
- Board Frame。
- Continuity。

但不允许把 H3 特有标签直接提升为 Storyboard Core 字段。

H3 / Future Model 的特殊字段继续归属于 Generation Profile、Prompt Skill、Validator 和 Provider Parameter Schema。

## 4.3 Story Order 与 Generation Context 分离

必须严格区分：

```text
Story Order
Shot 001 → Shot 002 → Shot 003
```

和：

```text
Generation Context
Shot A ──Context Link──> Shot B
```

Story Order 是创作顺序。

Context Link 是生成依赖 / 连续生成关系。

重新排序 Storyboard 不得静默篡改历史 Job 的 Context 来源。

# Phase S0 — Storyboard Domain Contract

目标：先把 Scene / Shot / Order / Board Frame 等概念定义正确，再开发复杂交互。

## S0.1 Scene Model

建立前端共享 Contract / Mock Domain：

```text
Scene
├─ id
├─ number
├─ title
├─ summary
├─ order_key
├─ location
├─ time_of_day
├─ notes
├─ planned_duration
└─ shot_ids[] / derived relation
```

要求：

- `id` 稳定，不因排序变化。
- Scene Number 为展示字段，可重新计算。
- Scene 可折叠。
- Scene 可为空。
- Scene 顺序支持调整。

### 验收

- Mock 至少提供 3 个 Scene。
- 支持 Empty Scene。
- 支持超长 Scene 名称。
- 支持不同 Shot 数量。

---

## S0.2 Shot / Task Contract

在现有 `ShotTask` 基础上建立 Storyboard 所需字段。

建议：

```text
StoryboardShot
├─ id
├─ task_id
├─ scene_id
├─ order_key
├─ number
├─ title
├─ summary
│
├─ script_source
├─ user_intent
├─ story_beat
│
├─ shot_size
├─ camera_movement
├─ planned_duration
│
├─ storyboard_frame
├─ asset_bindings
│
├─ prompt_state
├─ generation_profile_id
├─ task_status
├─ context_status
│
├─ primary_result_id
└─ result_count
```

注意：

- `Shot Number` 不是数据库 ID。
- 排序后可以重算 `S01-003` 等展示编号。
- `id / task_id` 必须保持稳定。
- UI 不得通过展示编号保存关系。

### 验收

拖动重排后：

- 展示编号可更新。
- Selection 保持在同一个 Shot。
- Context / Result / Asset 引用不丢失。

---

## S0.3 StoryboardFrame Contract

新增一等视觉对象：

```text
StoryboardFrame
├─ source_type
│  ├─ placeholder
│  ├─ imported_image
│  ├─ asset
│  ├─ video_frame
│  └─ primary_result_frame
├─ source_id
├─ preview_url
├─ frame_time（可选）
├─ crop / fit metadata（可选）
└─ updated_at
```

V0.2 不要求实现独立 AI Image Provider。

Frame 可以来自：

- 手动导入。
- Project Asset。
- Reference Video 抽帧 Mock。
- Primary Result 抽帧 Mock。

### 验收

Shot Card 始终有明确 Visual 区域；缺少素材时展示稳定 Placeholder，而不是布局塌陷。

---

## S0.4 Story Order Contract

建立独立的排序规则：

```text
Project
  Scene order
    Shot order
```

不得直接依赖数组 index 作为长期 ID。

至少定义：

- insert before。
- insert after。
- move within scene。
- move across scene。
- reorder scene。
- normalize display number。

### Gate S0

- Scene / Shot / Frame / Order 数据结构明确。
- 不依赖 H3。
- Story Order 与 Context Link 分离。
- Mock 数据可稳定生成不同规模 Storyboard。

- 点击空白取消选择。
- Scene 内范围选择。
- 跨 Scene 多选。

Selection 必须以稳定 Shot ID 为基础。

---

## S3.2 Shot 插入

在两张 Shot 之间提供明确插入入口。

支持：

```text
Insert Before
Insert After
New Next Shot
```

插入后：

- 自动选中新 Shot。
- 展示编号重新计算。
- 其他 Shot 的内部 ID 不改变。

---

## S3.3 Drag Reorder

必须支持：

- Scene 内拖动排序。
- 跨 Scene 拖动。
- 清晰 Drop Indicator。
- Auto Scroll。
- 拖动时保留 Selection。

严禁：

- 拖动过程中布局大幅跳动。
- Drop 后 Selection 丢失。

# Phase S7 — Story Continuity + Task Context

## S7.1 Previous / Next Story Context

每个 Shot 默认能看到：

```text

Current Shot
Next Story Shot
```

提供：

- Previous Frame。
- Current Frame。
- Next planned beat。
- 角色 / 场景变化摘要。

---

## S7.2 Context Link 显示

独立显示 Generation Context：

```text
Semantic
Visual
Audio
Latent / Native Context
Fallback
```

高级技术信息默认折叠。

Storyboard Card 只显示简洁状态，例如：

```text

```

Inspector / Composer 才显示详细来源。

---

## S7.3 Story Reorder Continuity Check

当用户改变 Story Order 时：

系统检查：

- Previous / Next Story Shot 是否改变。
- 当前 Context Link 是否仍指向合理上游。
- 已生成 Job 是否基于旧 Context。

不得自动改写历史 Job。

UI 可提示：

```text
连续性关系需要检查
```

---

## S7.4 Context Stale

以下情况至少触发 Mock `Context Stale`：

- 上游 Primary Result 改变。
- Context Link 来源改变。
- 已生成 Shot 被移动到另一上游之后，且仍使用旧 Generation Context。

提供动作：

```text
保持现有结果
更新 Context
从此处重新生成
```

V0.2 “从此处重新生成”可以先是 Mock 行为 / 队列预览，不要求真实 Scheduler。

---

## S7.5 Continuity Warnings

Storyboard 可提供轻量连续性提示：

- Character changed。
- Scene changed。
- Missing Previous Context。
- Primary Result missing。
- Context Stale。

避免做成强制规则引擎；警告应可解释、可忽略。

### Gate S7

Story Order 与 Generation Context 的关系对用户清晰，而且重新排序不会造成静默错误。

# Phase S9 — Result → Storyboard Integration

目标：让生成结果真正回到分镜，而不是只存在于独立 Result 页面。

# 7. V0.2 完成定义

V0.2 完成不是“有一个分镜页面”。

必须达到：

```text
用户可以进入一个 Scene
↓
看见真实视觉分镜板
↓
快速插入 / 复制 / 删除 / 排序 Shot
↓
在右侧直接改大多数镜头信息
↓
从大段剧本获得可审核的拆镜候选
↓
批量绑定角色 / 场景资产
↓
理解并检查镜头连续性与生成 Context
↓
需要时进入完整 Prompt Composer
↓
Mock Result 回到对应 Shot
↓
Primary Result 更新分镜视觉
↓
从头播放 Story Reel
```

并且整个过程中：

- 不要求用户频繁离开 Storyboard。
- 不把 Storyboard 做成 NLE。
- 不绑定 MiniMax-H3。
- 不把 Story Order 与 Generation Context 混为一谈。
- 不依赖展示编号作为内部关系 ID。
- 不破坏 V0.1 已验证的 Overlay、Prompt Composer 和 `@` Asset Editor 行为。

达到以上标准后，才进入下一阶段真实 Project Core / SQLite / Provider / ComfyUI 执行链路的大规模接入。
