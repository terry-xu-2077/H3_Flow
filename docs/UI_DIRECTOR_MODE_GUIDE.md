# ShotMill Director Mode UI 开发规范

> 状态：V0.4 起强制执行  
> 最后更新：2026-09-13  
> 适用范围：桌面端、`/dev/ui`、后续移动端工作流  
> 优先级：涉及前端信息密度、查看/编辑关系、任务编辑器结构时，本规范高于旧版 UI 约定。

## 0. 产品目标

ShotMill 不是参数控制台，也不是把后端领域模型直接投影到界面的工具。

最终产品必须让用户稳定地理解为：

```text
剧本 → 故事板 → 生成 → 看结果 / 局部返工
```

内部可以继续保留复杂的 Task、Context、Profile、Job、Result、Visual Beat 等模型，但这些复杂度默认不得泄漏给用户。

核心原则：

> **能力可以复杂，界面必须简单。**

> **查看和编辑必须分离。**

> **不要为了“信息完整”牺牲学习成本。**

---

## 1. 一级信息架构

桌面端只保留三个一级工作区：

1. **故事板**：创建、排列、查看和进入分镜编辑。
2. **生成**：查看队列、进度、失败和完成状态。
3. **素材**：管理角色、场景、道具、参考图、视频和音频。

不得再次增加以下一级入口：

- 结果；
- 项目设置；
- Provider；
- Profile；
- Prompt；
- Job；
- Context。

设置进入右上角设置按钮；结果回到分镜或生成记录；技术能力进入设置或调试页面。

---

## 2. 查看与编辑分离（强制）

这是 V0.4 开始最重要的交互规则。

### 2.1 单击 = 查看

用户单击一张分镜卡：

- 只选中该分镜；
- 右侧显示只读信息栏；
- 不进入编辑状态；
- 不出现输入框；
- 不自动打开任务编辑器。

右侧信息栏只能展示：

```text
代表画面
分镜名称
画面描述
时长
状态
已绑定素材
连续性摘要
```

右侧信息栏禁止出现：

- textarea / input；
- 保存按钮；
- 生成参数；
- Prompt；
- Profile；
- 高级设置；
- 添加素材；
- 任何会修改任务内容的控件。

### 2.2 双击 / 右键 = 编辑

编辑任务只有两个主入口：

- 双击分镜卡；
- 右键分镜卡 → `编辑分镜`。

编辑必须打开悬浮窗口，不得把主故事板切换成另一套复杂页面。

### 2.3 新建分镜

用户主动点击“添加分镜”属于明确的编辑意图，因此允许：

1. 创建空白分镜；
2. 选中它；
3. 直接打开同一套悬浮任务编辑窗。

不得为新建分镜再创建独立的“新建向导”。

---

## 3. 任务编辑窗最终结构

任务编辑窗采用固定两区结构：

```text
┌──────────────┬────────────────────────────────────┐
│   任务配置   │            提示词编辑              │
│              │                        用户 | AI增强│
│ 生成参数     │                                    │
│ 生成模式     │            大面积编辑区            │
│ 上下文承接   │                                    │
│              │                                    │
├──────────────┴────────────────────────────────────┤
│                               取消      保存       │
└───────────────────────────────────────────────────┘
```

### 3.1 左侧：任务配置

左侧只允许少量会直接改变生成行为的高频配置。

当前基线：

#### 生成参数

- 分辨率；
- 质量档位；
- 总秒数。

#### 生成模式

例如：

- 全能参考；
- 首尾帧。

#### 上下文承接

例如：

- 自动承接；
- 尾帧承接；
- 不承接。

不得在左栏直接平铺：

- Provider；
- 模型 Capability；
- Profile ID；
- Context Link；
- Job Snapshot；
- Validation；
- JSON 参数；
- Prompt Revision；
- Visual Beat 参数表。

### 3.2 右侧：提示词编辑

右侧是编辑窗的视觉中心，必须占据明显更多空间。

顶部只保留两个视图：

- **用户**：用户最终控制的提示词；
- **AI 增强**：AI 辅助生成或增强后的版本。

用户提示词支持 `@` 引用当前任务素材。

例如输入：

```text
主角 @
```

应出现角色、场景、图片、视频、音频等素材候选。

AI 增强稿不能自动覆盖用户稿。用户必须显式选择“采用增强结果”。

### 3.3 底部动作

任务编辑窗底部只允许两个稳定动作：

- 取消；
- 保存。

不要把“生成 Prompt / 验证 / Ready / 更新 Context / 加入队列 / 重新生成”等内部步骤放到底部动作栏。

---

## 4. 参数暴露预算

### 4.1 分镜卡

最多展示 5 类信息：

1. 代表画面；
2. 编号；
3. 标题 / 一句话描述；
4. 时长；
5. 用户可理解的状态。

默认不得显示：

- 生成方案名；
- 素材数量；
- 内部镜头数量；
- Prompt 状态；
- Context 类型；
- Job / Result ID；
- Provider；
- Capability；
- Validation 数量。

### 4.2 右侧只读信息栏

最多回答：

- 这是什么分镜？
- 它讲什么？
- 多长？
- 当前什么状态？
- 用了哪些素材？
- 是否和上一分镜连续？

不能演变成第二个编辑器。

### 4.3 生成队列

每行最多展示：

- 分镜；
- 状态；
- 进度；
- 必要异常动作。

### 4.4 素材卡

每张最多展示：

- 预览；
- 名称；
- 媒体类型 / 分类；
- 标签。

技术路径、素材 ID 等默认隐藏。

---

## 5. 全中文产品界面

普通产品界面默认使用中文。

允许保留：

- 产品名：ShotMill；
- 模型名：H3、Qwen 等；
- 文件格式；
- 分辨率：1080P、2K；
- 必须符合外部协议的引用标签，例如 `<Subject 1>`。

默认不得直接显示：

- Director Mode；
- Production；
- Project Media；
- Ready / Offline；
- Task Composer；
- Visual Beat；
- Generation Profile；
- Validator；
- Story Reel；
- Previous / Next / Play / Pause；
- Context Link；
- Final Prompt；
- AI Prompt Revision。

内部代码仍可使用英文命名，但产品文案必须翻译成创作语言。

---

## 6. 用户术语与内部术语隔离

| 内部概念 | 用户界面说法 |
| --- | --- |
| GenerationTask | 分镜 / 片段 |
| TaskVisualBeat | 内部镜头 / 镜头段落 |
| GenerationContextLink | 连续性 |
| Context Stale | 连续性需同步 |
| GenerationProfile | 生成方案 |
| Ready Validation | 生成前检查 |
| Job | 生成记录 |
| Result | 生成结果 |
| Provider | 生成服务 |
| Prompt Revision | 提示词版本 |

只有技术调试页面允许直接显示内部名词。

---

## 7. 故事板布局规则

默认故事板必须保持一个主画布：

```text
故事板                         连续预览 / 导入剧本 / 批量生成
────────────────────────────────────────────────────────
场景 01
[分镜] [分镜] [分镜] [+]

场景 02
[分镜] [分镜] [+]
```

禁止恢复：

```text
左侧导航器 | 中间任务板 | 右侧技术 Inspector
```

用户选中分镜后，只允许出现右侧只读信息栏。

---

## 8. 操作密度规则

### 8.1 一个区域只做一件事

- 故事板：组织画面；
- 右侧栏：看信息；
- 编辑窗：修改任务；
- 生成页：看生成；
- 素材页：管理素材。

禁止一个面板同时承担“看、改、生成、调试”四种职责。

### 8.2 系统可推导的步骤自动完成

如果系统可以安全判断：

- 当前生成方案；
- 是否需要连续性；
- 是否需要生成前检查；
- Job 快照；

则用户不应看到对应手工按钮。

### 8.3 不用缩小字号解决拥挤

信息过多时按以下顺序处理：

1. 删除；
2. 合并；
3. 延迟展示；
4. 移到设置 / 调试；
5. 最后才调整布局尺寸。

禁止：

- 一排大量 Badge；
- 多列 key-value 参数墙；
- 8px 以下正文；
- 四五个折叠区默认同时展开；
- 为了“完整”把后端字段全部映射出来。

---

## 9. 视觉气质

- 深色、中性色、低饱和度；
- 高饱和色只用于选中、警告、错误、关键动作；
- 图片 / 视频始终比 UI 装饰更重要；
- 少边框层级；
- 少 Badge；
- 少说明文字；
- 主要内容区宁可留白，也不要用参数填满；
- 编辑窗口应像创作工具，不像数据库后台。

---

## 10. 新功能进入 UI 前的强制审查

每增加一个字段、按钮、Badge、面板前必须回答：

1. 用户此刻在做什么？
2. 这个信息会改变用户当前决策吗？
3. 能否由系统自动判断？
4. 是否可以只在右侧只读栏展示？
5. 是否必须进入编辑窗？
6. 这是用户概念还是内部实现概念？
7. 是否已经在别的页面提供相同能力？

以下理由不能作为把参数放上界面的依据：

- “后端本来就有”；
- “信息更完整”；
- “以后可能有用”；
- “高级用户可能想看”；
- “空着也是空着”；
- “调试方便”。

---

## 11. 回归验收清单

涉及 UI 的 PR 必须检查：

- [ ] 一级导航是否仍然只有故事板 / 生成 / 素材？
- [ ] 卡片单击是否只查看，不编辑？
- [ ] 右侧栏是否完全只读？
- [ ] 双击是否打开悬浮任务编辑窗？
- [ ] 右键菜单是否提供“编辑分镜”？
- [ ] 任务编辑窗是否保持左侧少量配置 + 右侧大编辑区？
- [ ] 编辑窗底部是否只有取消 / 保存？
- [ ] 是否出现英文工程术语？
- [ ] 分镜卡是否超过 5 类信息？
- [ ] 是否出现参数墙、Badge 墙或 key-value 墙？
- [ ] 生成页是否再次出现任务编辑能力？
- [ ] 素材技术 ID / 路径是否默认隐藏？
- [ ] `/dev/ui` 是否覆盖空、正常、密集、运行中、失败、连续性失效等状态？

任何一项失败，都应先修正信息架构，再讨论视觉细节。

---

## 12. 当前基线

```text
故事板
├─ 场景
│  ├─ 分镜卡
│  └─ 添加分镜
├─ 单击分镜
│  └─ 右侧只读信息栏
├─ 双击分镜
│  └─ 悬浮任务编辑窗
└─ 右键分镜
   └─ 编辑分镜

任务编辑窗
├─ 左：任务配置
│  ├─ 生成参数
│  ├─ 生成模式
│  └─ 上下文承接
├─ 右：提示词编辑
│  ├─ 用户
│  └─ AI 增强
└─ 底部
   ├─ 取消
   └─ 保存

生成
└─ 只监控队列和异常

素材
└─ 只管理素材
```

最终判断标准只有一个：

> **用户第一次打开软件时，不应该需要先学习 ShotMill 的内部架构，才能开始做分镜。**
